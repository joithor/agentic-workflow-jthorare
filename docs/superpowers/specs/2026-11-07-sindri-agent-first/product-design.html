You describe it; an agent builds it; Sindri runs it

What the owner sees and does once this ships. Building happens in your agent's terminal; the app is where you look, never where you have to go.

4. How the functions work, with one example

Missed schedules run once. The drift check is due at 07:00 Monday to Friday. The laptop is closed from Thursday 19:00 to Monday 08:30. On wake, Sindri sees two missed ticks (Friday 07:00 and Monday 07:00; the weekend has none) and runs the workflow once, for Monday 07:00, then resumes at Tuesday 07:00.

Polling catches up. A Linear label was added Saturday 11:02. On wake, the catch-up reads the Linear cursor forward from Thursday 18:58 and finds it; the run starts within a minute with the label event's delivery id, so if the regular poll sees it too, nothing runs twice.

Decisions

D1Drop the approval concept entirely, for the profile and for workflows.
D2Agents get every verb; no gate between agents and running workflows. "The agents are good enough to test it out with me first."
D3Remove recipes entirely; drop the factory pipeline.
D4Agent-first via MCP; the app must be an option, never required.
D6Catch-up only: no webhooks; scan for what was missed while the machine was off.
D9Toolkits as a concept, all in C#.
